왜 그래프인가 · 1

지금까지의 RAG는 한 방향 직선이었다

간단한 흐름에는 충분합니다. 다만 “상황을 보고 판단”하거나 “될 때까지 되풀이”할 수 없습니다.
갈림길 · 반복 · 상태 공유를 그대로 코드로 옮길 수 있습니다.

왜 그래프인가 · 2

직선이 감당 못 하는 세 가지

BRANCH

갈림길

상황에 따라 다른 길로 갑니다. 짝수면 A, 홀수면 B. 에이전트라면 “도구를 쓸까, 그냥 답할까”.

LOOP

반복

조건이 될 때까지 같은 일을 되풀이합니다. 도구 결과를 보고 다시 생각하는 것도 반복입니다.

STATE

기억

여러 단계가 데이터를 공유하며 조금씩 바꿔갑니다. 대화 기록도 결국 공유되는 상태입니다.

다음 주 에이전트는 “생각 → 도구 필요? → 도구 실행 → 다시 생각”으로 움직입니다. 세 가지가 전부 필요하죠. 그래서 그래프입니다.

개념 · State · Node · Edge

그래프의 해부도

  • State — 상태그래프가 들고 다니는 공유 데이터. 📋 모두가 함께 보는 메모장.
  • Node — 노드상태를 읽고 바꾸는 함수. 🧑‍💼 일하는 담당자.
  • Edge — 엣지노드에서 노드로 가는 화살표. ➡️ 흐름선.
  • 되돌아오는 길같은 노드로 다시 향하는 엣지. 이것이 반복입니다.
딱 이 셋입니다. 오늘 나머지 시간은 이 셋을 어떻게 조합하느냐의 이야기입니다.

실습 · 노드 1개

첫 그래프 — 대문자로 외치기

State는 “모양” — TypedDict로 어떤 값을 들고 다닐지 정의 Node는 그냥 함수 — 바뀔 부분만 dict로 반환 조립은 세 줄 — add_node → add_edge → compile

📒 실습 노트북 Part 1

graph_01_single_node.py
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END

# ① State — 그래프가 들고 다닐 메모장의 모양
class State(TypedDict):
    text: str

# ② Node — 상태를 받아 '바뀔 부분만' 반환
def shout(state: State):
    return {"text": state["text"].upper() + "!"}

# ③ 조립
builder = StateGraph(State)
builder.add_node("shout", shout)     # 담당자 등록
builder.add_edge(START, "shout")     # 시작 → shout
builder.add_edge("shout", END)       # shout → 끝
graph = builder.compile()

graph.invoke({"text": "hello"})      # {'text': 'HELLO!'}

실습 · 노드 여러 개

상태가 노드를 지나며 조금씩 바뀐다

상태 number가 노드를 거치며 3 → 4 → 8로 흘러갑니다. 여러 단계 작업을 노드로 쪼개 순서대로 잇는 것이 그래프의 기본입니다.

📒 실습 노트북 Part 2

graph_02_sequence.py
class State(TypedDict):
    number: int

def add_one(state): return {"number": state["number"] + 1}
def double(state):  return {"number": state["number"] * 2}

builder = StateGraph(State)
builder.add_node("add_one", add_one)
builder.add_node("double", double)

builder.add_edge(START, "add_one")
builder.add_edge("add_one", "double")   # 이 순서로 흐른다
builder.add_edge("double", END)
graph = builder.compile()

graph.invoke({"number": 3})   # {'number': 8}

State 자세히 · Reducer

덮어쓰기 vs 이어붙이기

노드가 어떤 값을 반환하면 기본적으로 그 값으로 바꿔치기 합니다. 그래서 여러 노드가 같은 필드를 건드리면 마지막 값만 남습니다.

덮어쓰기 — 기본값

steps: list
node_a["A 실행"]
→
node_b["B 실행"]
→
결과"A 실행" ["B 실행"]
앞의 값이 사라집니다. 기록을 쌓아야 하는 곳에선 치명적이죠.

이어붙이기 — Reducer를 붙였을 때

steps: Annotated[list, operator.add]
node_a["A 실행"]
→
node_b["B 실행"]
→
결과["A 실행", "B 실행"]
리스트끼리 더해져 쌓입니다. 한 줄 차이입니다.
Reducer는 “같은 필드에 새 값이 오면 어떻게 합칠지” 정하는 규칙입니다. 규칙이 없으면 덮어쓰고, operator.add를 붙이면 이어붙입니다.

State 자세히 · 코드

한 줄로 규칙을 바꾼다

graph_03_reducer.py
import operator
from typing import Annotated

class State(TypedDict):
    steps: Annotated[list, operator.add]   # ← "이어붙여라"

def node_a(state): return {"steps": ["A 실행"]}
def node_b(state): return {"steps": ["B 실행"]}

# A → B 순서로 실행하면 둘 다 쌓인다
# {'steps': ['A 실행', 'B 실행']}
다음 주 예고

add_messages도 Reducer입니다

15주차에서 대화 기록을 담을 때 쓰는 add_messages는 “메시지를 덮어쓰지 말고 이어붙여라”는 규칙, 즉 메시지 전용 Reducer입니다. 지금 원리를 이해하면 다음 주가 쉬워집니다.

갈림길 · Conditional Edges

상황을 보고 다른 길로

route — 상태를 보고 표지판 이름을 반환 지도 — 이름표를 실제 노드로 연결

📒 실습 노트북 Part 4

graph_04_branch.py
class State(TypedDict):
    number: int
    result: str

def even_node(state): return {"result": "짝수입니다"}
def odd_node(state):  return {"result": "홀수입니다"}

# 라우터 — 어디로 갈지 '이름표'를 반환
def route(state):
    return "even" if state["number"] % 2 == 0 else "odd"

builder.add_conditional_edges(
    START, route,
    {"even": "even_node", "odd": "odd_node"}   # 이름표 → 노드
)

graph.invoke({"number": 4})   # 짝수입니다
graph.invoke({"number": 7})   # 홀수입니다

반복 · Loop

되돌아오는 화살표가 반복이 된다

무한 루프 주의 — 반복에는 반드시 멈추는 조건이 있어야 합니다. LangGraph는 안전을 위해 기본 25번까지만 돌고 멈춥니다(recursion_limit).

📒 실습 노트북 Part 5

graph_05_loop.py
class State(TypedDict):
    count: int

def increment(state):
    new = state["count"] + 1
    print(f"count: {new}")
    return {"count": new}

# 5 미만이면 계속, 아니면 끝
def should_continue(state):
    return "continue" if state["count"] < 5 else "end"

builder.add_node("increment", increment)
builder.add_edge(START, "increment")
builder.add_conditional_edges(
    "increment", should_continue,
    {"continue": "increment", "end": END}   # 자기 자신으로
)

graph.invoke({"count": 0})   # count: 1, 2, 3, 4, 5

graph_06_llm_node.py
from langchain_google_genai import ChatGoogleGenerativeAI

llm = ChatGoogleGenerativeAI(model="gemini-2.0-flash",
                             temperature=0)

class QAState(TypedDict):
    question: str
    answer: str

def ask_llm(state: QAState):          # 노드 안에서 LLM 호출
    response = llm.invoke(state["question"])
    return {"answer": response.content}

builder = StateGraph(QAState)
builder.add_node("ask_llm", ask_llm)
builder.add_edge(START, "ask_llm")
builder.add_edge("ask_llm", END)
qa_graph = builder.compile()

qa_graph.invoke({"question": "LangGraph를 한 문장으로"})

정리 · 코드 패턴

이 형태만 기억하면 됩니다

langgraph_pattern.py
from typing import Annotated
from langgraph.graph import StateGraph, START, END
import operator

# ① 상태 — 이어붙일 필드엔 reducer
class State(TypedDict):
    number: int
    log: Annotated[list, operator.add]

# ② 노드 — 바뀔 부분만 반환
def step(state):
    return {"number": state["number"] + 1, "log": ["실행"]}

# ③ 라우터 — 갈 곳의 이름표 반환
def route(state):
    return "again" if state["number"] < 5 else "end"

# ④ 조립 — 노드 등록 → 엣지 연결 → compile
builder = StateGraph(State)
builder.add_node("step", step)
builder.add_edge(START, "step")
builder.add_conditional_edges("step", route,
                              {"again": "step", "end": END})
graph = builder.compile()
순서

① 상태 → ② 노드 → ③ 라우터 → ④ 조립

어떤 그래프를 만들든 이 네 단계입니다. 복잡한 그래프는 ②와 ③이 늘어날 뿐, 뼈대는 같습니다.

막힐 때 1 — 상태에 필드가 빠지지 않았나 막힐 때 2 — 라우터가 반환한 이름표가 지도에 있나 막힐 때 3 — 루프에 멈춤 조건이 있나
